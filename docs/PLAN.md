# Development Plan: NFC Card Platform

Source of truth: [PRD.md](PRD.md). Phases follow the PRD milestones (M1–M5) with an added Phase 0.
Product scopes from the PRD are called v1 / v2 / v3 here to avoid clashing with these build phases.
Rule: one phase per session; review and pass the gate before starting the next.

## Phase 3 (M3): Admin panel
- [x] Admin login: email + bcrypt password, signed httpOnly session cookie (`jose`, 7 days, instead of Auth.js: one admin, no OAuth needed), `proxy.ts` on `/admin/*` only, `requireAdmin()` in every page and action, login rate limiting (10/IP and 5/email per 15 min), `npm run admin:create`
- [x] Clients list at `/admin/clients`: search (name, username, email), tier/status/usage filters, sort, paging (25), `paidUntil` and last-tapped columns, usage and renewal badges; filters are a plain GET form so every view has a URL
- [x] New/edit page form at `/admin/pages/new` and `/admin/pages/[username]`: driven by `getEntitlements` (tier, accent, fonts, banner, custom templates), username suggestion and availability check, status and paid-until, add-ons; live phone-width preview (the real template in an iframe, 320-430 px, light/dark); one shared validator for the client and the Server Action; optional sections are kept as they are until the Standard templates exist
- [x] Social link editor (add, remove, reorder, links built from handles, tile notes)
- [x] Image fields (photo, logo): paste a link, with a thumbnail preview and a disabled "Upload and crop" button as the placeholder. The real upload moves to the last step (needs the Cloudinary account)
- [x] Cards (panel on the edit page, saves at once): code generation (unambiguous alphabet), chip link and QR link with copy, per-card QR (SVG, PNG download), disable / mark lost / turn on, spare cards (max 10), rename, reset usage (deletes the card's taps and recomputes the page's last tap), delete a never-used card; per-card and page tap totals. Checked with real taps: a lost or disabled card shows the inactive page, and the page QR moves to the next active card
- [x] Renewals screen (`/admin/renewals`: terms ending within 30 days or already ended, with stage badges for due / grace / lapsed, reminder-sent mark, ready-made reminder email, renew +4 years, mark inactive, edit counter) and dashboard (`/admin`: active pages, taps this week, renewals due, drafts, live pages by usage status with links to the filtered list, next renewals). The edit counter is also on the page editor
- [x] Admin restyle in the homepage look (cream background, Bricolage Grotesque and Inter, rounded cards, pill buttons, orange accents, a "jibun. admin" header with the current page marked, a new sign-in screen); data screens stay compact. - [ ] Missing section designs (52 across the 8 templates, listed in `docs/SECTION-DESIGN-BRIEF.md`): waiting for the designs from Claude Design, then convert them. Priority: video and booking (no template has them), then gallery on the notebook and résumé on the social templates
- [x] Add-on sections on the Starter design: a Starter page now draws the sections a paid add-on unlocks (gallery, PDF/résumé, and later video and booking) with the same designs as Standard (`drawnKinds` in `templates/supported-sections.ts`); the free "pick 2" sections, reordering and font pairs stay Standard only. Still missing designs: video and booking in every template, and the sections listed in the coverage brief
- [x] Save Contact, second version: the button opens the contact the way the reference designs do. The vCard text is built on the server into the page and handed to the phone as a file made inside the tap (the version with the photo is fetched when a finger nears the button and used if it arrived), with no "Opening your contact" message. Without scripts the link still goes to `/vcard`. Needs a check on a real iPhone

- [x] Order form for clients (`/order?plan=standard&addons=gallery,video&template=pro-classic`, no database): the client answers on their phone and gets one message (a readable summary plus a code ending in a dot) to send in the chat; New page has a "Start from a client order" box that fills the whole page form from the pasted message; a link builder on the dashboard and on New page makes the links. Photos are sent in the chat until upload exists. Tests: `order.test.ts`, `order-import.test.ts`, `e2e/order.spec.ts`; the Privacy page says the form stores nothing

## Phase 5 (M5): Launch polish
- [x] Marketing homepage at `/` (converted from `design-reference/jibun-businesspage/`; `src/components/marketing/`, wording in `src/lib/marketing.ts`, brief in `docs/HOMEPAGE-BRIEF.md`). Deviations from the reference: self-hosted fonts, sticky header kept working (`overflow-x: clip`), darker "No" text for contrast. The six sample images in `public/marketing/` are screenshots and need replacing if a template changes
- [x] Lighthouse mobile (Lighthouse 12, default mobile throttling, all 8 templates in the Standard design): accessibility 100, best practices 100, performance 88–92 (between runs it moves by about 3 points), SEO 66 on purpose (client pages are `noindex`). The big win: every page was preloading the fonts of all eight templates (11 files, about 0.5 MB); template fonts now use `preload: false`, so a page downloads only the fonts it uses (performance went from about 77 to 88–92). Also fixed: a duplicate accessible name on the `pro-company` link tiles, and low-contrast ghost numerals and org badges. Left as is: all templates' CSS is one shared bundle (about 30 KB of it unused on any page) and Next's own JavaScript (about 135 KB); `inlineCss` and lazy template loading were tried and made it worse
- [x] Playwright tests: tap → page → vCard (`npm run test:e2e`, `e2e/tap-flow.spec.ts`: redirect and no-store, page shows the person, vCard content, QR image, tap logged without an IP, unknown/lost/lapsed cards go to /inactive; fixture rows are created and removed per run). Note: an unknown username shows the default Next.js "page could not be found" page with status 200 (the page streams); a branded not-found page is a later polish item
